# 開発サイクル・運用ルール

## Issue駆動開発
- 各タスクはIssueを作成して行う
- Issueごとにブランチを切って作業する
- Issueの作成はAI（Claude）任せでよい。ただし作成されたIssueの内容は必ず目視で確認する

## ブランチ管理
- GitHub Flowを踏襲する
- 1サイクル: Issue作成 → ブランチ作成 → 実装 → 単体テスト → push → プルリクエスト作成 → レビュー → mainへマージ

## テスト
- Issueごとに単体テスト（JUnit）を実施する
- 余裕があればE2Eテストを行う（開発終盤でよい）

## Claude・GitHub連携
- パーソナルアクセストークンを使用してClaudeとGitHubを連携する
- パーソナルアクセストークンはClaudeに渡さない・チャットに流さない（セキュリティ上のリスクを避けるため）
- 連携時はトークンを環境変数から読み込ませる形にする

## 秘匿情報の扱い
- `.env` をはじめとする秘匿情報はGitHubやClaudeに渡さない

## ドキュメントとの同期
- 資料関連と実装内容は常に同期されているべき
- 例: 実装で `docs/database-design.md` にないテーブル変更を行った場合は、必ず同ファイルも更新する

## データベースの確認
- データベースの中身確認にはSQLクライアントを使ってよい
  - 例: [HeidiSQL](https://www.heidisql.com/)
