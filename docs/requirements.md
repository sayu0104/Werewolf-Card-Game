# ブラウザ人狼ゲーム 要件定義書

## 1. プロジェクト概要

### 1.1 コンセプト
人狼ゲームとカードゲーム（デッキ系）を融合させたブラウザゲーム。
発言の"印象"（強気/弱気、疑う/擁護など）をフリーテキストではなくカードとして表現することで、
心理戦の駆け引きを戦略的なカードプレイに落とし込む。

### 1.2 目標
- **1人プレイ対応を最重要目標とする**（複数人プレイも将来的に対応）
- AIキャラクターとのチャット機能により、実際に複数人でプレイしているかのような没入感を実現する
- AIキャラクターの難易度調整機能を用意する
- 少人数でもAIキャラクターで人数を補い、人狼ゲームとして成立させる

### 1.3 想定プレイスタイル
- 個人開発のポートフォリオとして、完成後にネット上へ公開予定
- 技術スタックはSpring Boot + MySQLを基本とする（[[java-study]]の学習内容と連続性を持たせる）

## 2. MVPスコープ

### 2.1 対応役職（MVP: 5役職）
| 役職 | 陣営 | 概要 |
|---|---|---|
| 村人 | 村人陣営 | 専用カードを持つ（詳細は今後検討） |
| 人狼 | 人狼陣営 | 夜に襲撃を行う。複数人いる場合はお互いを認識する |
| 占い師 | 村人陣営 | 夜に対象を占い、朝に結果が判明する。占い師自身が死亡しても結果は判明する |
| 狩人 | 村人陣営 | 夜に対象を護衛する。護衛は人狼の襲撃より優先処理される |
| 狂人 | 人狼陣営（人狼の正体は知らない） | 昼に発動し昼に結果が出る「偽占い」カードを持つ。場をかき乱す役割 |

> 将来的に第三陣営（妖狐など）の追加を想定し、役職割り振りシステムはそれに対応できる設計とする。

### 2.2 ゲーム進行フェーズ
1. **朝**：前夜の結果（襲撃・護衛・占い結果）が判明する
2. **昼**：議論フェーズ。プレイヤーはカードを使って議論する（基本ターン制、複数人プレイ時はオプションで時間制）
3. **投票**：全員同時投票。同票の場合は同数だった者同士で再投票
4. **夜**：役職ごとの行動フェーズ（占い・護衛・襲撃など）

### 2.3 処刑・勝敗
- 処刑者の役職は**非公開**とする
- 処刑確定後、処刑者に最後の発言機会（遺言システム）を与える
- 勝利条件の厳密な定義は今後検討（未確定事項、5章参照）

## 3. カードシステム

### 3.1 カードの種類
- **役職専用カード**：役職ごとに毎ターン1枚必ず配布される（占い・護衛・襲撃・偽占いなど）
- **基本カード**：全役職共通で使える汎用カード（疑う・擁護・疑いをそらす、など）。山札制（1ゲームで大体1巡する設計）でドローする

### 3.2 カード公開ルール
- カードを「使った」こと自体は全役職共通で他プレイヤーに見える
- 何のカードを使ったかは、役職専用カード（占い・護衛など）は非公開とし、「疑う」など基本カードは役職ごとに公開/非公開を設定する

### 3.3 コストルール
- 1ターンあたりの**共通コストプール制**（仮上限5）を採用
- 占いカード（占い師・コスト1・強制使用）
- 偽占いカード（狂人専用・コスト1・任意使用）
- 護衛カード（コスト1以上、コスト0にはしない＝毎ターン確実な護衛を避ける）
- 襲撃カード（人狼専用。コストは共通プール上限5に対して重すぎない値に調整する。仮4は重すぎるとの判断で再検討中）
- カード使用枚数から役職が推測されないよう、各役職のカード使用可能枚数の目安を揃える

### 3.4 占い・偽占いカードの仕様
- 対象選択は都度記録・固定するが、結果（白/黒）の解釈は申告時に1回だけ確定する
- 本物の占い師の占いカードはコスト1・強制使用
- 狂人の偽占いカードはコスト1・任意使用

### 3.5 打ち消し・妨害要素
- 「役職能力そのものを無効化」案、「誤情報カード」案は不採用
- 「人狼複数時の護衛突破カード」案は採用候補（人狼の襲撃人数ルールと連動して要決定、5章参照）
- 人狼専用の「疑いを逸らすカード」など、1ゲーム1回限定の希少カードは「使うまで手札に残り続ける」保留枠として扱う

## 4. 被疑心ポイント

- カード使用（疑う/擁護など）によってプレイヤーごとに蓄積されるポイント
- 活用方針（A・B路線で確定）
  - A：カード使用制限に直結させる
  - B：一定値を超えると強制イベントが発生する
- 具体的な数値・閾値は未確定（5章参照）

---

## 5. 未確定事項（今後の検討課題）

- 人狼陣営内の連携の詳細（人狼は複数いる場合お互いを認識する設定は確定済み）
- 投票の細部（得票数のみ公開する案が仮候補。村人の役職専用カードとして「誰が誰に投票したか見えるカード」を検討中）
- 勝利条件の厳密な定義
- 打ち消し・妨害要素の具体化（護衛突破カードの採否は人狼襲撃人数ルールと連動）
- 人狼が複数いる場合の1晩の襲撃可能人数（1晩1人までとしつつ、人数の恩恵を成功率・確実性や議論での余力に反映する案を検討中）
- 1人プレイ時の具体的なプレイ感（AI人数の割合、テンポなど）
- カードの入手・所持方法の詳細（山札制は決定済み。基本カードの総枚数・構成は未定）
- 村人専用カードの具体的な効果（強すぎない範囲で検討中）
- 村人の小役職細分化（余裕があれば優先的に取り組みたい将来対応）

---

## 6. AIキャラクター仕様

- 抽象的な初級/中級/上級ラベルではなく、キャラクターごとに以下のパラメータを紐づけて管理する
  - 判断の最適性
  - 一貫性チェック（発言や行動のブレの少なさ）
  - 欺瞞の巧妙さ
  - 口調・性格
- AIによる長期記憶の限界（ターンが進むと過去の発言を忘れる懸念）への対応方法は今後の実装課題

---

## 7. 役職割り振り（1人プレイ／少人数プレイ対応）

- プレイヤーは役職ごとに「確定で入れる」「ランダムで入れる（いないかもしれない）」「入れない」をカスタム設定できる
- 確定役職の合計人数が総人数を超える場合は、理由付きのエラーを表示する
- 将来的に第三陣営を追加した際、「村人陣営 vs 第三陣営（人狼なし）」のような対戦構成にも対応できる設計とする
- AI人数はなるべく増やせるようにする方向性
